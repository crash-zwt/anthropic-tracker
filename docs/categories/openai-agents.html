How avatarin built a 24/7 retail agent with GPT-Realtime

Original Link

TL;DR

OpenAI 发了一篇偏 field-report 的客户案例：avatarin 用 GPT-Realtime 为日本 Yamada Denki 搭了一个 24/7 multilingual shopping agent，两周触达约 30,000 名用户，post-use survey 92% positive。技术重点不在新 API，而在 single-model multimodal conversation、RAG grounding、以及会主动追问需求的 conversation design。

Key Points

  • agent 同时处理语音、文本和图像理解，核心卖点是低延迟自然对话，而不是传统 keyword chatbot。
  • 系统用 RAG 保证商品信息准确，再把门店销售经验编码进 prompts、conversation flows 和 guardrails。
  • 设计重点是让 agent 主动追问用户约束条件，例如家庭人数、预算、空间等，而不是被动答 FAQ。
  • 两周 public campaign 内约 30,000 用户实际使用，说明 GPT-Realtime 已经能支撑真实零售流量，而不只是 demo。
  • 对方把每轮对话当成 customer-insight capture 工具，这比单纯的在线客服替代更有长期价值。

Why It Matters

这篇文章的信号是 realtime multimodal agent 已经从展示型场景进入真实商业流程，尤其适合服务、导购、支持这类需要持续澄清需求的场景。对做 voice agent 的团队来说，比较有价值的是它把 RAG、prompting、brand persona 和 survey loop 放到了一个闭环里。

My Take

内容偏 polished customer story，技术新意有限，但 deployment pattern 很值得抄。真正重要的不是“92% positive”这种 PR 指标，而是他们明确把 GPT-Realtime 用成了一个会主动收集约束、同时保留品牌语气的 conversation engine。如果你在做 commerce/support agent，这篇比泛泛的成功案例更有可落地细节。

Introducing OpenAI Presence

Original Link

TL;DR

OpenAI 在 2026-07-22 发布 Presence，这不是单纯的 model launch，而是一个面向 enterprise 的 deployed agent product：围绕 voice / chat agents，把 policy、guardrails、approved actions、simulation、evaluation 和 Codex-powered improvement process 打包进同一套交付面。官方把它定位成“让高价值 workflow 里的 agents 可控地进 production”的系统，而不是 self-serve API feature。

Key Points

  • Presence 面向具体 job deployment：例如 billing、insurance claims、employee IT support，agent 只拿完成该任务所需的 knowledge 和 system access
  • 控制面由企业定义，包括可执行动作、何时需要 approval、何时升级给人，OpenAI 强调的是 policy / escalation / guardrail 而不只是更强模型
  • 上线前会用 simulations 和 graders 测 outcome correctness、policy compliance、tool use、escalation behavior；上线后再根据 production session 和 escalation 信号持续迭代
  • Codex 在这里扮演 post-launch improvement engine：根据真实 session 信号提出更新建议，团队可先对比 production 版本测试，再做 controlled rollout
  • OpenAI 给出的最硬数字是：其英文电话支持渠道 1-888-GPT-0090 已由 Presence 驱动，75% inbound issues 无需人工处理，且 Codex-driven loop 在 10 天内把 human handoff 再降了 15 个百分点

Why It Matters

Presence 的信号在于 OpenAI 正把 agents 商业化为一套带 deployment service、evaluation layer 和 managed improvement loop 的 operating model。对企业买方来说，这比单独购买模型更接近“可上线系统”；对开发者生态来说，也意味着 agent platform 的竞争点正在从 reasoning 质量转向 governance、simulation 和 post-launch adaptation。

My Take

这是一个值得重点记录的 agent product move。它说明 OpenAI 想卖的不只是 frontier model，而是带 FDE 和 systems integrator 的 vertically integrated deployment stack。我的保留判断是：这类产品的真实壁垒不在 demo，而在实施成本、交付速度和客户是否愿意接受非 self-serve 的交付模式；但从方向上看，它已经比普通 enterprise case study 更像一个完整产品线。

How Cars24 scales conversations and builds faster with OpenAI

Original Link

TL;DR

OpenAI 发布 Cars24 案例：这家汽车交易平台用 voice/chat agents 覆盖买车、卖车、融资、回访和售后，官方给出的结果是每月处理 100 万+ conversation minutes、客服 resolution rate 提升 50%、关键服务流程 turnaround time 降低 80%，并通过 AI re-engagement 挽回 12% 原本流失的 seller leads。内部侧，Cars24 还把 Codex 和 ChatGPT Enterprise 推到约 600 名员工，日活达到 85% 到 90%。

Key Points

  • 外部 agent 场景很完整：从 lead qualification、test drive booking、financing support 到售后 follow-up，覆盖整条车交易链路而不只是单一客服入口
  • 指标里最有业务味道的是 12% lost seller leads recovery，这说明 agents 不只省人工，还直接作用在中后漏斗转化
  • Cars24 把 Codex 嵌进 software development lifecycle：PM 用它生成和细化 Linear tickets，工程团队把 Codex 挂进 bug reports，自动汇总 GitHub 进展
  • 文章还展示了 agentic workflows 向 finance、investor relations、采购审批等部门扩散，甚至出现连接 Slack、Gmail、WhatsApp 的 chief of staff agents
  • 整体信号是 OpenAI 不再只卖模型，而是在卖“agents + Codex + org workflow redesign”的 operating layer

Why It Matters

这类案例的价值在于它把 agent 产品从 demo 拉回到组织流程：前台是高频对话自动化，后台是 Codex 驱动的内部执行和跨部门工具化。对关注 agent ROI 的人来说，这比泛泛的 adoption 叙事更接近真实落地样本。

My Take

这是偏商业案例的官方材料，但细节比一般客户故事扎实，尤其是把 Codex 放进 Linear / GitHub / bug 流里这一段。需要保留的怀疑同样明确：所有效果指标都是自报，没有对照组和成本拆解。不过它至少说明，大公司正在把 coding agent 从“工程师个人工具”升级为跨团队的 workflow substrate。

ChatGPT is now a partner for your most ambitious work

Original Link

TL;DR

OpenAI 发布 ChatGPT Work：一个能跨 apps/files 行动、长时间保持项目上下文、把目标拆成步骤并产出 sheets/slides/docs/web apps 的 agent。它内置 Codex technology，由 GPT-5.6 驱动，定位从问答助手升级为工作执行伙伴。

Key Points

  • ChatGPT Work 可跨 web、mobile、desktop 和用户文件/应用收集信息并产出完成品
  • 内置 Codex technology；OpenAI 称 Codex 每周已有 500 万用户，其中 100 万用于非软件开发工作
  • 支持长达数小时的 complex projects，可跟踪进度、向用户提问、改变方向并请求关键操作审批
  • 示例包括预算 variance analysis、campaign brief、sales meeting prep、Scheduled Tasks 自动更新 docs/slides
  • 强调组织安全与治理，明显对标 Claude Cowork / enterprise agents

Why It Matters

这是 OpenAI agent 产品线的重要扩展：Codex 不再只是 coding agent，而是成为一般办公 agent 的底层执行技术。它把 ChatGPT 从 conversational interface 推向 cross-app workflow executor。

My Take

这篇很重要。ChatGPT Work 的方向和 Claude Cowork/Claude Code converging：都在抢“能在真实工具里完成工作”的入口。关键挑战会是权限、安全、可追溯、失败恢复和用户信任。产品承诺很大，真实体验需要重点观察。
