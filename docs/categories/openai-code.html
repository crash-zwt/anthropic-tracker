NTT DATA Group cuts incident analysis to 30 minutes with Codex

Original Link

TL;DR

OpenAI 在 2026-07-22 发布这篇 NTT DATA Group case study，核心不是新模型，而是 Codex 在大型 IT 服务企业里的 organization rollout：先用 ChatGPT Enterprise 建立 AI 使用习惯，再把 Codex 扩到约 9,000 名技术和非技术员工，去执行 incident analysis、跨文件 automation 和 reporting 这类边界清晰的任务。最硬的 proof point 是一次原本需要 5 名资深工程师 3 天完成的复杂 incident analysis，被 Codex 压到 30 分钟。

Key Points

  • NTT DATA Group 先在全公司铺开 ChatGPT Enterprise，并由内部 OpenAI Center of Excellence 负责 license、validation、events、usage monitoring 和 knowledge sharing，为后续 Codex rollout 打基础
  • 最早打出声量的 use case 是 critical system 的 incident analysis：原来要 5 位 experienced engineers 做 3 天，改成 Codex agent 后 30 分钟完成，直接让高层看到 agentic execution 的价值
  • 使用场景已经从 engineering 扩到 nontechnical roles，包括整理大量文件、分析 Excel 数据、生成报告，以及把信用卡账单中的交通支出转录到差旅报销表
  • 为了让 9,000 人放心用，NTT DATA Group 明确了 data usage、system access、network handling、sandbox mode、automation level 和 human review 的安全治理规则
  • 官方给出的进一步结果包括：通过 usage guide 和 hands-on training，把 weekly active Codex users 拉高 1.4 倍；还用 Playwright 做内部系统自动化，并把能力封装成 reusable Skills

Why It Matters

对这个 tracker 来说，这类 post 的价值在于它展示 Codex 正从 developer assistant 变成 enterprise task-execution layer。重点不只是“写代码更快”，而是把明确、可验证、跨文件或跨系统的工作流程委托给 agent，并用 CoE、training、policy 和 sandbox governance 去支撑规模化扩散。相比泛泛 customer story，这篇给了更像真实 rollout playbook 的 operational detail。

My Take

我会把这篇评为 medium practical signal。亮点是 adoption path 很真实：先铺 ChatGPT Enterprise，再由 CoE、security rules、training 和 reusable Skills 把 Codex 扩散到更广的人群。保留点也很明确：30 分钟 incident analysis 是很强的 flagship example，但长期价值取决于这些 automations 能否在更多 team 中稳定复用，而不是靠少数 champion case 拉动叙事。

How Codex became a collaborator for OpenAI’s creative team

Original Link

TL;DR

OpenAI 这篇 2026-07-16 的 internal case study 试图把 Codex 从 engineering tool 扩写成 creative workflow collaborator。文章主角是 OpenAI Creative Specialist Chad Nelson：他不是用 Codex 直接替代创意判断，而是把它当成理解 brief、品牌手册、style guide、构图约束和 prototype intent 的技术搭档，用来快速搭工具、扩写 campaign directions，并缩短从概念到可操作原型的距离。

Key Points

  • 文章强调 Codex 对 creative team 的价值不只是 copywriting，而是理解品牌上下文后帮忙搭自定义工具、UI、sliders 和 visual workflow
  • 一个具体用法是把 brand books、design style guides、composition constraints 等非传统代码材料交给 Codex，让它围绕项目上下文生成更贴近 brief 的工具与方向
  • 在创意发散阶段，OpenAI 给出的例子是：原本也许只能探索 5 到 10 个 campaign directions，现在能在一天内生成 50 个方向，再由人筛到最强的 10 个
  • Codex 被放在 concepting、workflow design 和 technical implementation 的交界处，减少 creative idea 到 working prototype 之间的 handoff friction
  • 整篇文章的 framing 仍然是 human-in-the-loop：更多 options、更快原型，但最后的 taste、selection 和 judgment 仍由 creative team 自己承担

Why It Matters

这类案例对 tracker 的意义在于，它把 Codex 的扩散范围继续从 software engineering 推向 broader knowledge and creative work。和单纯“某客户提效”不同，这篇更像在验证一个命题：如果 agent 能理解 full-project context，它就不只是写代码工具，而会变成跨职能的 workflow substrate。

My Take

我会给 medium practical signal。文章最有价值的是它没有把创意工作讲成完全自动化，而是强调 Codex 帮人更快搭工具、探索更多方向、减少技术阻塞。这比空泛地说“AI 赋能创意”更可信。限制同样明显：官方没有给出太多 hard metrics，除了更快 idea expansion 之外，长期价值还要看这些 bespoke workflows 能不能被更广泛复用。

Separating signal from noise in coding evaluations

Original Link

TL;DR

OpenAI 审计 SWE-Bench Pro 后认为约 30% 任务有 broken/invalid 问题，包括过严测试、prompt 信息不足、低覆盖测试和误导性 prompt。这会让 coding agent eval 结果失真，影响模型发布与安全判断。

Key Points

  • OpenAI 对 731-task public split 做数据质量审计，自动 pipeline 标记 200 个 broken tasks，人工标注识别 249 个
  • 主要问题包括 hidden tests 强制 prompt 未说明的实现细节、prompt underspecified、测试覆盖不足、prompt 与测试目标矛盾
  • 前沿模型在 SWE-Bench Pro public split 8 个月内从 23.3% pass rate 到 80.3%，benchmark 质量变得更关键
  • 审计流程结合 model attempts、task metadata、failure traces、investigator agents 和 5 位 experienced software engineers
  • 文章建议 model developers 谨慎解读 SWE-Bench Pro 结果，并把 eval quality 当作能力测量的一部分

Why It Matters

对 Codex/Claude Code 这类 coding agent 来说，eval 本身会决定产品叙事和安全部署。如果 benchmark 30% broken，榜单提升可能混入大量噪音，甚至误导模型训练和 release 决策。

My Take

这是本轮最有工程价值的 OpenAI research post。它提醒我们：agent eval 不只是跑分，而是数据集质量、任务 specification 和测试公平性的系统工程。也说明未来 coding benchmark 会越来越需要 agent-assisted auditing + human review。
