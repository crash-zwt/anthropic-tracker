Interaction Models: A Scalable Approach to Human-AI Collaboration - Thinking Machines Lab

Original Link

TL;DR

Thinking Machines Lab 发布 Interaction Models 研究预览，提出将 interactivity 作为模型原生能力而非外部 scaffolding。核心是 time-aware 的 micro-turn 架构（200ms chunks），支持全双工 audio/video/text 并发输入输出，配合异步 background model 处理深度推理。TML-Interaction-Small（276B MoE, 12B active）在 FD-bench 交互质量上大幅领先 GPT-Realtime 和 Gemini，同时保持有竞争力的智能 benchmarks。

Key Points

  • 原生 interactivity 设计：模型从 scratch 训练，采用 multi-stream micro-turn 架构，200ms 级别的连续 input/output 交错，无需 VAD 等 turn-detection harness
  • 双模型架构：real-time interaction model 负责即时响应，background model 异步处理 tool calls、browsing、深度推理，两者共享 context
  • Encoder-free early fusion：audio 用 dMel、video 用 40x40 patches，轻量 embedding layer 直接进入 transformer，所有组件 co-trained
  • 新 benchmark 维度：TimeSpeak/CueSpeak 测试时间感知和 simultaneous speech；RepCount-A/ProactiveVideoQA 测试 visual proactivity——现有模型在这些任务上基本失效
  • Inference 优化：streaming sessions 避免频繁内存重分配，已 upstream 到 SGLang；MoE kernel 用 gather+gemv 策略优化 latency
  • 模型规格：TML-Interaction-Small 为 276B MoE（12B active），更大模型计划今年晚些时候发布

Why It Matters

这篇工作直接挑战了当前 frontier models 的核心假设：turn-based interface 是瓶颈而非特性。对于关注 agents 和 human-AI collaboration 的人来说，这代表了一条不同的路线——不是让 AI 更 autonomous，而是让 AI 成为更好的 real-time collaborator。技术层面，encoder-free early fusion 和 micro-turn 设计可能成为 multimodal real-time models 的新范式。对 OpenAI/Google 的 realtime APIs 构成直接竞争压力。

My Take

这是 Mira Murati 离开 OpenAI 后新 lab 的首篇重磅研究，方向选择很有意思——不做另一个 frontier LLM，而是专注 interaction 这个被低估的维度。技术执行看起来扎实，benchmark 设计有说服力，尤其是 visual proactivity 维度暴露了现有 realtime APIs 的盲区。但 276B MoE 的 serving cost 和 latency 要求意味着部署门槛很高，long sessions 的 context 管理仍是 open problem。关键问题是：这条路线能否 scale 到 frontier intelligence？还是说 interactivity 和 raw intelligence 之间存在 trade-off？需要等更大模型发布才能判断。另外 2026 年 5 月的时间戳可能是 future-dated 的营销选择，实际技术值得认真对待。

Training LLMs to Predict World Events (Guest Post with Mantic) - Thinking Machines Lab

Original Link

TL;DR

Mantic 团队通过 RL fine-tuning 将 gpt-oss-120b 的 forecasting 性能从 38.6 提升到 45.8（Metaculus baseline score），达到与 Gemini 3 Pro、GPT-5 等 frontier LLMs 持平的水平。关键发现：fine-tuned model 在 optimal ensemble 中权重占 40%，与 Grok 4 同为最不可替代的成员——因为其预测策略准确但与其他模型 decorrelated。实验在 Tinker 平台上完成，使用 ~10k binary questions 和 Brier score 作为 reward。

Key Points

  • RL fine-tuning 让较小的 open-source model (gpt-oss-120b) 追平 frontier LLMs 的 forecasting 性能
  • Forecasting-specific context（research phase + mixture model tools）对 training dynamics 至关重要，无此条件时 gain 减半
  • Ensemble 中 diversity 比 raw accuracy 更重要：fine-tuned model 和 Grok 4 因预测 decorrelated 而成为最不可替代成员
  • Training 技术细节：GRPO-style advantage normalization、Brier score 比 log score 更稳定、batch size 64、group size 8
  • 实验基于 Metaculus AI Benchmark Q2 2025，测试集为 unseen questions，knowledge cutoff 严格控制在 tournament 开始前

Why It Matters

这篇 post 展示了一条实用路径：用 RL fine-tuning + domain-specific tools 让 open-source model 在垂直任务上追平 frontier models。对关注 agents 和 alignment 的研究者来说，这是 'specialization beats scale' 的一个 clean case study——forecasting 是一个 well-defined、有 ground truth 的任务，适合作为 RL 方法论的 testbed。同时，ensemble diversity 的发现对 model deployment strategy 有直接启发。

My Take

技术扎实、实验设计 clean，但创新性中等——RL fine-tuning for forecasting 已有先例（Turtel et al. 2025），本文贡献主要是验证了在更 realistic 的 research+prediction pipeline 中同样有效。真正有价值的是 ensemble analysis：揭示了 Grok 4 和 fine-tuned model 的 decorrelation property，这对 production system 的 model selection 有直接指导意义。局限：只测试了 binary questions，numerical/multiple choice 尚在进行中；gpt-oss-120b 本身不是主流 model，结论的 generalizability 待验证。

On-Policy Distillation - Thinking Machines Lab

Original Link

TL;DR

Thinking Machines 提出 on-policy distillation 方法，结合了 RL 的 on-policy sampling 和 distillation 的 dense reward signal。核心思路：从 student model 采样 trajectories，用 teacher model 对每个 token 打分（reverse KL），实现比 RL 高 9-30x 的 compute efficiency。实验在 AIME'24 math reasoning 上验证，并展示了该方法在 continual learning 场景下恢复 post-training behavior 的实用性。

Key Points

  • On-policy distillation 用 reverse KL 作为 per-token reward，比 RL 的 sparse reward 更 compute-efficient，Qwen3 报告显示用 1/10 的 GPU hours 达到更高 AIME'24 分数
  • 方法实现简单：在 RL script 基础上只需 swap regularizer model，用 teacher 的 logprobs 计算 reverse KL 作为 advantage
  • Math reasoning 实验：从 SFT-400K checkpoint 出发，on-policy distillation 用 ~77K prompts 达到 70% AIME'24，相比 extrapolated SFT-2M 节省 9-30x compute
  • Personalization/continual learning 实验：mid-training on new knowledge 会 degrade instruction-following behavior，on-policy distillation 用原模型作为 teacher 可以 recover 这些能力
  • 关键 insight：dense supervision 让每个 token 都有学习信号，而 RL 只在 episode 结束时给一个 binary reward
  • Limitation：文章末尾被截断，RL vs on-policy distillation 的直接对比实验不完整

Why It Matters

对关注 model training efficiency 和 post-training stack 的人来说，这篇提供了实用的方法。On-policy distillation 本质上是 DAGGER 思想在 LLM 上的应用，解决了 off-policy distillation 的 distribution shift 问题，同时避免了 RL 的 sparse reward 问题。对于需要 continual learning 或 domain adaptation 的场景（如 enterprise assistant），用原模型作为 teacher 来 recover behavior 是一个简单有效的 trick。

My Take

方法本身不新（Agarwal 2023、Gu 2023、Qwen3 technical report 都做过），但 Thinking Machines 的 presentation 和实验设计很清晰。Personalization 实验比 math reasoning 更有实用价值——展示了如何在注入新知识的同时保持 instruction-following 能力。不过文章被截断，缺少 RL baseline 的完整对比。对于 practitioners，这是一个 low-effort high-reward 的方法：实现成本低（one-line change on RL script），compute savings 显著。值得在自己的 domain adaptation 场景复现验证。

LoRA Without Regret - Thinking Machines Lab

Original Link

TL;DR

John Schulman 离开 OpenAI 加入 Thinking Machines 后的首篇重磅研究，系统性回答了一个核心问题：LoRA 能否 match FullFT 的性能？答案是肯定的——只要把关键细节做对。文章通过大量实验证明，在 post-training 的典型场景下，LoRA 可以达到与 FullFT 相同的 sample efficiency 和最终性能，并给出了具体的 hyperparameter 设置指南。

Key Points

  • LoRA 要应用在所有 layers（尤其是 MLP/MoE），attention-only LoRA 即使 rank 更高也显著 underperform，这个发现挑战了原始 LoRA paper 的建议
  • RL 场景下 LoRA 完全 match FullFT，甚至 rank=1 就够了——因为 policy gradient 每个 episode 只提供 O(1) bits 信息，远低于 supervised learning 的 O(tokens) bits
  • LoRA 的 optimal learning rate 约为 FullFT 的 10x，这个比例在不同模型和任务上稳定出现，可以直接用于 hyperparameter transfer
  • 大 batch size 下 LoRA 会有额外 penalty，这是 product-of-matrices parametrization 的固有属性，与 rank 无关
  • LoRA capacity 不足时表现为 training efficiency 下降而非 loss floor，可通过 rank 相对 dataset size 来判断是否进入 low-regret regime
  • 文章给出了 parametrization invariances 的理论分析，说明 4 个 hyperparameters 中只有 2 个真正独立，简化了调参难度

Why It Matters

这是 John Schulman（PPO 作者、OpenAI 前 lead）在新 lab 的首篇技术文章，质量很高。对于做 post-training、RLHF、或 model deployment 的团队，这篇工作提供了 LoRA 使用的 practical guide，解决了 'LoRA 是否够用' 的疑虑。特别重要的是 RL 只需极低 capacity 的发现——这对 reasoning model 训练（如 DeepSeek-R1 风格的 RL）有直接指导意义。文章也解释了为什么 vLLM/SGLang 等 inference engine 都在大力支持 multi-tenant LoRA serving。

My Take

Modular Manifolds - Thinking Machines Lab

Original Link

TL;DR

Thinking Machines Lab 的 Jeremy Bernstein 发表了一篇关于 manifold optimization 的技术博客，提出了 manifold Muon optimizer——将权重矩阵约束在 Stiefel manifold 上（所有 singular values 为 1），并引入 modular manifolds 理论来系统性地 budget learning rates across layers。核心思想是通过 manifold constraints 保证 weight matrices 的健康状态，避免训练过程中的数值问题。

Key Points

  • 提出了 manifold Muon：结合 Stiefel manifold constraint（W^T W = I）和 spectral norm，用 dual ascent 求解 optimal update direction
  • 推导了完整的 manifold optimization 框架：tangent space projection → learning rate scaling → retraction map back to manifold
  • 引入 modular manifolds 理论：通过 Lipschitz sensitivity 分析自动 budget 各层 learning rates，实现 layer-wise optimizer 的模块化组合
  • 小规模实验显示 manifold Muon 在 CIFAR-10 MLP 上优于 AdamW，但 wall clock overhead 需要优化（dual ascent iterations）
  • 与 Jianlin Su 和 Franz Louis Cesista 的独立工作形成对话，提供了 dual ascent 视角的解决方案
  • 提出了多个 future directions：attention heads 的 manifold 设计、low-precision training 兼容性、non-Riemannian geometry 的理论拓展

Why It Matters

这是训练稳定性研究的 deep tech 贡献。Muon optimizer 近期在社区获得关注，这篇工作将其扩展到 manifold constraint setting，提供了更严格的 theoretical grounding。对于关心 training stability、Lipschitz constraints、以及 optimizer design 的 researcher 来说，这是一篇值得细读的技术文章。Modular manifolds 的 abstraction 可能对 large-scale training 的 hyperparameter tuning 有实际价值。

My Take

这是一篇扎实的技术博客，但 practical impact 还需要验证。实验规模太小（CIFAR-10 MLP），overhead 问题（dual ascent iterations）在 LLM scale 下可能更严重。不过 modular manifolds 的理论框架很有启发性——把 layer-wise learning rate budgeting 和 Lipschitz analysis 统一起来是个 elegant 的 idea。建议关注：1）是否有后续的大规模实验；2）Polar Express 等 fast matrix sign 算法能否降低 overhead；3）与 weight decay、其他 regularization 技术的交互。对于做 training infrastructure 的团队，值得跟踪但不急于 adopt。

Defeating Nondeterminism in LLM Inference - Thinking Machines Lab

Original Link

TL;DR

Thinking Machines 深入分析了 LLM inference 即使在 temperature=0 时仍然 nondeterministic 的真正原因——不是 GPU concurrency 或 floating-point non-associativity，而是 kernels 缺乏 batch invariance：当 server load 变化导致 batch size 变化时，同一个 request 会得到不同结果。文章提出了 batch-invariant 的 RMSNorm、matmul、attention 实现方案，代价是约 20% 性能损失。

Key Points

  • 常见误解：LLM inference nondeterminism 不是因为 GPU concurrency + floating-point non-associativity——实际上 forward pass 的 kernels 都是 run-to-run deterministic 的，且几乎没有 atomic adds
  • 真正原因：kernels 缺乏 batch invariance——同一个 request 在不同 batch size 下会得到不同数值结果，因为 reduction order 会随 batch size 变化而改变
  • 三个需要处理的 operation：RMSNorm、matrix multiplication、attention——都需要保证 reduction order 不受 batch size 影响
  • 实现 batch invariance 的代价：matmul 相比 cuBLAS 损失约 20% 性能，主要因为无法使用 split-k 和需要固定 tile size
  • Attention 的额外挑战：需要处理 KV cache、chunked prefill、prefix caching 等场景，保证 reduction order 不受 sequence slicing 方式影响
  • 实际意义：实现真正的 determinism 对 RL training（尤其是 on-policy RL）和 scientific reproducibility 至关重要

Why It Matters

对于做 RLHF、on-policy RL training 的团队，determinism 是保证 training stability 和 reproducibility 的基础。对于 inference service providers，这篇文章揭示了为什么即使设置了 temperature=0 也无法保证相同输出——这是 API 用户经常抱怨的问题。理解 batch invariance 的概念有助于评估 inference engines 的设计 tradeoffs。

My Take

这是一篇技术深度很高的工程向文章，清晰地 debunk 了社区关于 GPU nondeterminism 的常见误解。核心 insight——batch invariance 才是关键——非常 practical。20% 的性能损失对于需要 reproducibility 的场景（如 RL training、scientific experiments）是可接受的，但对于 production inference 可能需要权衡。文章没有提供开源实现，但给出了足够的技术细节让有经验的 kernel engineer 可以复现。对于大多数 practitioners，这篇文章的价值在于理解 determinism 的真正成本和 tradeoffs。
